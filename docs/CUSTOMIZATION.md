# S2 Admin customization plan

S2 Admin is a custom derivative of the TailAdmin free **HTML/Webpack + Tailwind CSS v4 + Alpine.js** template, version `2.4.0` in the checked-out `package.json`. It is not a Next.js/React template.

## Work in `s2-admin` branch

Keep upstream-specific assets and project-specific changes clearly separated. When visual requirements are confirmed, document and implement brand assets, typography, color tokens, sidebar/nav labels and responsive breakpoints. Prefer a small project-specific CSS layer and component/partial additions rather than changing TailAdmin's vendor CSS everywhere; the intent is to make upstream merges manageable.

The current clone retains TailAdmin's own appearance. No S2 Admin theme, logos, authentication, client data, or business integration has been chosen or activated by setup.

Recommended customization order:
1. Define whether this is one reusable admin UI kit or a specific app, then brand/design tokens.
2. Establish common responsive shell: logo/header/sidebar/topbar, navigation, dark/light.
3. Create reusable UI components: tables, forms, cards, modals, toasts, empty states, pagination.
4. Establish accessibility, small-screen sizing and contrast checks.
5. Decide auth, permissions and data/API adapters for each real app; the existing demo is **not** a secure production admin system.
6. Run build and UI QA, then deploy through that project's release SOP.

### Existing commands

```powershell
cd 'D:\dev\s2-admin'
npm ci --ignore-scripts --no-audit --no-fund
npm run build
npm start
```

Note that `npm start` launches a local development server and opens a browser; it is **not** a public deployment. Do not start it unattended or publish it on a public interface.
